# LH CONVERT-GATE 프로젝트 기획안

## 0. Claude Code 작업 지침

이 문서는 프로젝트의 기준 문서다. 구현 중 임의로 범위를 확장하지 말고, 아래 MVP 범위와 우선순위를 따른다.

핵심 원칙:

1. 법규 적합성은 생성형 AI가 임의로 판정하지 않는다.
2. 법규와 LH 기준은 버전이 기록된 규칙엔진으로 판정한다.
3. 머신러닝은 도면·BIM의 공간과 객체를 인식하고 유사 사례를 찾는 데 사용한다.
4. 강화학습은 법규를 만족하는 개선행동의 조합과 순서를 탐색하는 데 사용한다.
5. 법규 위반 대안은 보상 감점이 아니라 행동 마스킹 또는 하드 제약으로 제거한다.
6. 강화학습의 효과는 규칙 기반, 탐욕 알고리즘, 수리최적화와 반드시 비교한다.
7. 초기 MVP는 실제 법적 인허가 판정기가 아니라 연구용 사전진단 프로토타입이다.
8. 모든 결과에는 적용 규칙, 입력 데이터, 계산 근거, 불확실성을 함께 표시한다.

# 1. 프로젝트 개요

## 1.1 프로젝트명

LH CONVERT-GATE

## 1.2 한글 제목

비주택 매입 후보 건축물의 공공임대주택 전환 가능성 및 최소개선 대안 자동진단 시스템

## 1.3 핵심 아이디어

기존 비주택 건축물의 건축물대장, 평면도, BIM 정보를 분석하여 공공임대주택으로 용도변경할 때 새롭게 적용되는 건축·소방·피난·주차·편의시설 기준을 도출한다. 이후 현재 건물의 미충족 공간과 부재를 찾고, 법규를 하드 제약조건으로 설정한 강화학습을 이용하여 공급세대 수, 공사비, 공사기간, 기존 시설 재사용률을 고려한 최소개선 대안을 생성한다.

## 1.4 발표용 핵심 문장

머신러닝이 바꿔야 할 곳을 찾고, 강화학습이 가장 경제적인 변경 조합을 만든다.

## 1.5 해결하려는 질문

- 이 비주택 건물을 공공임대주택으로 전환할 수 있는가?
- 현재 용도에서 주거 용도로 바뀌면서 새롭게 적용되는 기준은 무엇인가?
- 기존 건물에서 어떤 공간과 부재가 기준을 충족하지 못하는가?
- 어디를 얼마나 고치면 몇 세대를 공급할 수 있는가?
- 공급량, 사업비, 공사기간을 고려할 때 가장 적절한 개선안은 무엇인가?

# 2. 문제 정의

비주택 건축물을 공공임대주택으로 전환하려면 건축, 소방, 피난, 주차, 장애인 편의시설, 설비, 에너지 등 여러 기준을 동시에 검토해야 한다. 현재는 담당자와 전문가가 건축물대장, 도면, 현장조사 결과, 법령과 설계기준을 개별적으로 대조한다.

이 과정에서 다음 문제가 발생한다.

- 검토해야 할 기준이 여러 법령과 지침에 분산되어 있다.
- 현재 용도와 목표 용도에 따라 새롭게 발생하는 의무사항이 달라진다.
- 같은 후보 건물도 평면, 코어, 창호, 계단, 설비 위치에 따라 전환 가능성이 달라진다.
- 법규를 충족시키는 개선방법이 여러 개이므로 공급세대 수와 비용 사이의 비교가 필요하다.
- 후보 건물이 많을 때 동일한 수준으로 빠르게 사전검토하기 어렵다.
- 검토자의 경험에 따라 결과와 우선순위가 달라질 수 있다.

본 시스템은 법률 자문이나 최종 인허가를 대체하지 않는다. 후보 건물의 매입 및 정밀검토 이전에 사용하는 사전 의사결정 지원 도구를 목표로 한다.

# 3. 목표 사용자와 사용 시나리오

## 3.1 목표 사용자

- LH 매입임대사업 담당자
- 공공리모델링 사업 담당자
- 건축사 및 용도전환 설계자
- 소방·피난·설비 검토 담당자
- 후보 건물 현장조사 담당자
- 사업비 및 공정 검토 담당자

## 3.2 대표 시나리오

현재 용도가 업무시설인 건물의 3층부터 8층까지를 청년 공공임대주택으로 전환한다고 가정한다.

사용자는 다음 데이터를 입력한다.

- 건축물대장 정보
- 기존 평면도 PDF 또는 이미지
- IFC 또는 Revit에서 추출한 BIM 데이터
- 현재 용도와 목표 용도
- 변경 대상 층과 면적
- 기존 주차대수
- 기존 소방시설 정보
- 현장 실측값
- 목표 세대 유형과 최소 면적
- 사업비 상한과 목표 공사기간

시스템은 다음 결과를 출력한다.

- 용도변경 절차 후보
- 신규 적용 또는 강화되는 검토기준
- 현재 건물의 미충족 후보 위치
- 자동검토, 현장실측, 전문가판단 항목 구분
- 개선행동 후보
- 공급량 우선안, 비용 우선안, 균형안
- 대안별 공급세대 수, 공사비, 기간, 면적효율
- 적용 규칙과 계산 근거

# 4. MVP 범위

초기 개발 범위는 반드시 다음으로 제한한다.

## 4.1 대상 용도변경

업무시설에서 청년 공공임대주택으로 전환하는 사례 1종

## 4.2 대상 공간

- 건물 전체가 아니라 기준층 1개 층
- 전용면적 약 800~1,500제곱미터
- 코어 1~2개
- 계획 세대 10~30세대

## 4.3 검토 분야

1. 공간 및 세대구획
2. 피난동선과 출구
3. 방화구획 및 방화문
4. 주요 소방시설 배치
5. 채광·환기 후보검토
6. 주차대수 계산
7. 장애인 접근성 후보검토

초기 MVP에서 구조안전, 상세 설비용량, 에너지 시뮬레이션, 실제 인허가 서류 자동제출은 제외한다.

## 4.4 개선행동 종류

초기 강화학습 행동은 아래 8종 이내로 제한한다.

1. 비내력벽 추가
2. 비내력벽 삭제
3. 출입문 위치 변경
4. 일반문을 방화문으로 변경
5. 방화구획 추가
6. 스프링클러 헤드 추가 또는 이동
7. 두 세대를 통합
8. 특정 세대 계획 제외

행동은 임의의 연속 좌표가 아니라 미리 생성된 후보 위치 중 하나를 선택하도록 한다.

# 5. 전체 시스템 구조

```text
건축물대장 / 평면도 / IFC / 현장실측
                ↓
데이터 정규화 및 건물 그래프 생성
                ↓
머신러닝 기반 공간·객체 인식
                ↓
현재 용도와 목표 용도의 규제 차이 계산
                ↓
규칙엔진 기반 미충족 항목 판정
                ↓
개선행동 후보 자동 생성
                ↓
하드 제약조건 기반 행동 마스킹
                ↓
강화학습 기반 개선행동 조합 탐색
                ↓
공사비·공기·공급세대 평가
                ↓
Pareto 대안 및 근거 보고서 출력
```

# 6. 기술별 역할 분담

## 6.1 규칙엔진

규칙엔진은 법규 및 설계기준 판정을 담당한다.

주요 역할:

- 현재 용도와 목표 용도의 적용기준 비교
- 신규 적용, 강화 적용, 유지, 전문가 확인으로 분류
- 공간 및 객체 속성과 기준값 비교
- 위반 또는 추가 확인이 필요한 위치 식별
- 강화학습에서 선택할 수 없는 행동을 마스킹
- 결과마다 법령명, 조항, 시행일, 적용조건 기록

중요 원칙:

- 생성형 AI의 답변을 법적 판정값으로 사용하지 않는다.
- 규칙은 JSON 또는 데이터베이스 레코드로 관리한다.
- 모든 규칙에 버전, 시행일, 출처, 검토상태를 저장한다.

예시 규칙 스키마:

```json
{
  "rule_id": "FIRE_EGRESS_001",
  "domain": "egress",
  "source_name": "official_rule_source",
  "source_article": "article_reference",
  "effective_from": "YYYY-MM-DD",
  "effective_to": null,
  "applies_when": {
    "target_use": ["public_rental_housing"],
    "floor_condition": "example_condition"
  },
  "required_fields": ["travel_distance", "exit_count"],
  "check_type": "numeric_threshold",
  "operator": "lte",
  "threshold": "versioned_value",
  "unit": "m",
  "result_on_missing": "expert_review"
}
```

## 6.2 머신러닝

머신러닝은 법규를 판단하는 것이 아니라 입력 데이터를 구조화한다.

### 기능 A. 평면도 객체 인식

입력:

- 평면도 이미지 또는 PDF에서 추출한 이미지

출력:

- 벽
- 문
- 창호
- 계단
- 복도
- 화장실
- 샤프트
- 소방시설 기호
- 공간 경계

초기에는 BIM 또는 벡터 도면 데이터가 있으면 규칙 기반 추출을 우선 사용한다. 이미지 ML은 BIM이 없는 오래된 건물의 보완 기능으로 둔다.

### 기능 B. 공간 용도 분류

텍스트, 면적, 인접관계, 설비 객체를 이용해 공간 용도를 추정한다.

예시:

- 사무실
- 복도
- 계단실
- 기계실
- 화장실
- 창고
- 주거 세대 후보

### 기능 C. 유사 사례 검색

건물 및 층 평면을 임베딩하여 유사한 전환 사례를 검색한다.

검색 특성 예시:

- 코어 유형
- 창호 간격
- 외벽 길이
- 층고
- 기둥 그리드
- 샤프트 위치
- 계단 수
- 전용면적
- 목표 세대 유형

### 기능 D. 비용·공기 보정 모델

초기 MVP에서는 표준단가와 공정 계산식을 사용한다. 실제 전환사례가 축적된 이후 회귀모델로 예측값을 보정한다.

초기 공모전에서는 ML 비용예측을 핵심 성과로 주장하지 않는다.

## 6.3 강화학습

강화학습은 법규를 충족하는 개선행동의 조합과 순서를 찾는다.

적용 목적:

- 공급세대 수 최대화
- 개선공사비 최소화
- 공사기간 최소화
- 철거량 최소화
- 기존 코어와 설비 재사용률 최대화
- 법규 미충족 항목 제거

강화학습이 법적 허가 여부를 결정하지 않는다. 최종 대안은 전문가가 승인한다.

# 7. 강화학습 환경 설계

## 7.1 환경

Gymnasium 호환 사용자 정의 환경으로 구현한다.

환경 이름 예시:

`ConversionRetrofitEnv`

## 7.2 상태 State

상태는 건물 그래프, 현재 설계상태, 규칙 위반, 비용과 공기 누적값으로 구성한다.

최소 상태값:

- 공간 수
- 세대 후보 수
- 세대별 면적
- 채광 가능 외벽 길이
- 문과 계단의 연결 그래프
- 출구까지의 최단거리
- 방화구획 상태
- 주요 소방시설 배치
- 현재 법규 미충족 항목 수
- 현재까지 선택한 개선행동
- 누적 공사비
- 누적 공사기간
- 남은 예산
- 철거 및 신설 물량

그래프 표현 예시:

- 노드: 공간, 문, 계단, 샤프트, 세대
- 엣지: 인접, 출입 가능, 설비 연결, 피난 연결
- 속성: 면적, 용도, 폭, 내화성능, 층, 위치

## 7.3 행동 Action

행동은 `행동유형 + 대상 후보 ID` 조합으로 구성한다.

예시:

- ADD_WALL(candidate_wall_03)
- REMOVE_WALL(wall_21)
- MOVE_DOOR(door_05, candidate_position_02)
- CHANGE_TO_FIRE_DOOR(door_08)
- ADD_FIRE_COMPARTMENT(zone_02)
- MOVE_SPRINKLER(sprinkler_14, candidate_position_07)
- MERGE_UNITS(unit_03, unit_04)
- REMOVE_UNIT(unit_11)
- STOP

초기에는 연속적인 자유형 평면생성을 하지 않는다.

## 7.4 행동 마스킹

규칙엔진과 구조적 조건을 이용해 불가능하거나 위험한 행동을 사전에 제거한다.

마스킹 예시:

- 구조벽 삭제 금지
- 기둥과 코어 삭제 금지
- 법규상 최소 통로폭을 더 악화시키는 행동 금지
- 설비 샤프트에서 과도하게 먼 주방·화장실 생성 금지
- 예산을 즉시 초과하는 행동 금지
- 출구 연결을 끊는 행동 금지
- 이미 삭제된 객체에 대한 중복행동 금지

## 7.5 보상 Reward

예시 보상구조:

```text
reward =
  + w1 * compliant_unit_count
  + w2 * net_usable_area
  + w3 * reused_component_ratio
  + w4 * resolved_violation_count
  - w5 * retrofit_cost
  - w6 * construction_duration
  - w7 * demolition_quantity
  - w8 * MEP_relocation_distance
  - w9 * unresolved_expert_review_count
```

중요:

- 법규 위반 대안은 큰 음수 보상만 주는 방식에 의존하지 않는다.
- 치명적 위반은 행동 마스킹 또는 즉시 실패 상태로 처리한다.
- 보상 가중치는 설정파일로 분리한다.
- 공급량 우선, 비용 우선, 균형형 정책을 각각 학습할 수 있도록 한다.

## 7.6 종료조건

- STOP 행동 선택
- 모든 필수 위반 해소
- 최대 행동 횟수 도달
- 예산 초과
- 유효 세대 수가 최소 기준 미만
- 실행 가능한 행동이 없음

## 7.7 알고리즘

MVP 권장 알고리즘:

- `MaskablePPO` from `sb3-contrib`

비교 알고리즘:

- 무작위 탐색
- 규칙 기반 탐욕 알고리즘
- 유전알고리즘 또는 NSGA-II
- OR-Tools CP-SAT 기반 수리최적화

강화학습이 비교기법보다 항상 우수하다고 가정하지 않는다. 평가 결과에 따라 수리최적화와 강화학습의 하이브리드 구조로 변경할 수 있다.

# 8. 추천 하이브리드 최적화 구조

강화학습을 단독으로 사용하는 것보다 아래 구조를 우선 검토한다.

```text
규칙엔진
  ↓
법규를 만족할 수 있는 행동 후보 생성
  ↓
CP-SAT 또는 휴리스틱으로 초기 가능해 생성
  ↓
강화학습이 변동 조건에서 개선행동 순서를 재조정
  ↓
다목적 평가로 Pareto 대안 생성
```

역할:

- 규칙엔진: 불가능한 대안 제거
- 수리최적화: 정적 조건에서 강한 기준해 생성
- 강화학습: 건물 형상, 예산, 목표 공급량이 바뀌는 환경에 재사용
- 다목적 평가: 비용, 기간, 공급량 간 대안 제시

# 9. 데이터 구축 계획

## 9.1 기본 BIM 모델

최소 5개 기본 유형을 직접 제작한다.

1. 중앙코어형 업무시설
2. 편심코어형 업무시설
3. 양단코어형 업무시설
4. 깊은 평면형 업무시설
5. 중정 또는 비정형 평면형 업무시설

각 모델의 변형요소:

- 층 면적
- 기둥 그리드
- 창호 간격
- 계단 수
- 코어 위치
- 샤프트 위치
- 층고
- 외벽 길이
- 기존 소방시설 수

## 9.2 합성 시나리오 생성

하나의 기준 모델에서 다음을 조합한다.

- 세대 배치안
- 세대 크기
- 복도 위치
- 출입문 위치
- 방화구획
- 소방시설 배치
- 예산
- 목표 세대 수
- 공사기간 상한

이 조합으로 수백~수천 개의 환경을 자동 생성한다.

## 9.3 정답 데이터

정답은 세 종류로 구분한다.

1. 규칙엔진 정답
   - 수치기준 충족 여부
   - 객체와 공간의 연결조건
   - 필수 입력 누락 여부

2. 전문가 검토 정답
   - 자동판정하기 어려운 법령
   - 현장실측이 필요한 항목
   - 해석이 필요한 예외사항

3. 최적화 비교 정답
   - 소규모 문제는 완전탐색 또는 CP-SAT으로 기준해 생성
   - RL 결과와 목적함수 및 계산시간 비교

## 9.4 도면 인식 데이터

초기에는 직접 제작한 BIM에서 2D 평면 이미지를 렌더링하여 합성 학습데이터를 만든다.

각 이미지에 다음 라벨을 자동 생성한다.

- 벽 세그멘테이션 마스크
- 문 바운딩박스
- 창호 바운딩박스
- 공간 폴리곤
- 계단 및 샤프트 마스크
- 공간 용도

실제 공개도면을 평가용으로 일부 추가하되, 저작권과 개인정보를 확인한다.

# 10. 기능 요구사항

## 10.1 입력 및 데이터 관리

- FR-001: 건축물 기본정보를 JSON 또는 폼으로 입력한다.

- FR-004: 현재 용도와 목표 용도를 선택한다.
- FR-005: 변경 대상 층과 면적을 지정한다.
- FR-006: 법령과 기준의 적용 기준일을 선택한다.

## 10.2 분석

- FR-101: 현재 용도와 목표 용도의 규제 차이를 생성한다.
- FR-102: 신규, 강화, 유지, 전문가 확인 항목으로 분류한다.
- FR-103: BIM 또는 평면에서 공간과 객체를 추출한다.
- FR-104: 피난 연결 그래프와 최단거리를 계산한다.
- FR-105: 방화구획과 소방시설 후보를 표시한다.
- FR-106: 미충족 항목을 공간 및 객체 ID와 연결한다.
- FR-107: 데이터가 부족하면 부적합이 아니라 현장실측 또는 전문가 확인으로 분류한다.

## 10.3 개선안 생성

- FR-201: 개선행동 후보를 자동 생성한다.
- FR-202: 불가능한 행동을 규칙엔진으로 마스킹한다.
- FR-203: 강화학습을 통해 행동 조합을 탐색한다.
- FR-204: 기준 알고리즘과 결과를 비교한다.
- FR-205: 공급량 우선, 비용 우선, 균형형 대안을 생성한다.

## 10.4 결과

- FR-301: 개선 전후 평면 또는 3D 모델을 비교한다.
- FR-302: 각 대안의 세대 수, 비용, 기간, 면적효율을 표시한다.
- FR-303: 미충족 및 개선 객체를 색상으로 표시한다.
- FR-304: 적용 규칙과 계산 근거를 출력한다.
- FR-305: 자동검토, 현장실측, 전문가 확인 항목을 구분한다.
- FR-306: PDF 또는 HTML 사전진단 보고서를 생성한다.

동일한 건물과 동일한 예산에서 각 알고리즘을 30회 이상 실행한다.

시나리오 변화:

- 예산 10퍼센트 감소
- 목표 세대 수 증가
- 특정 출구 사용 불가

- 특정 벽 변경 불가
- 소방시설 단가 상승

# 19. 리스크와 대응방안

## 리스크 1. 기존 BIM 법규검토 기술과 중복

대응:

- 일반적인 법규검토가 아니라 용도변경 전후의 규제 차이 분석에 집중한다.
- LH의 비주택 매입 여부와 최소개선 사업성 판단으로 목적을 제한한다.
- 체크리스트 생성보다 개선대안과 공급세대·사업비 비교를 핵심으로 한다.

## 리스크 2. 강화학습이 불필요하다는 지적

대응:

- CP-SAT, NSGA-II, 탐욕 알고리즘과 정량 비교한다.
- 새로운 건물과 예산변동에서 정책 재사용성을 평가한다.
- RL이 불리하면 하이브리드 최적화로 전환한다.

## 리스크 3. 법령 오판

대응:

- 규칙엔진을 버전 관리한다.
- 전문가 검토 전 규칙은 연구용 상태로 표시한다.
- 입력 부족 시 부적합으로 확정하지 않고 확인 필요로 분류한다.
- 결과에 법적 최종판정이 아니라 사전진단임을 명시한다.

## 리스크 4. 실제 공사비 데이터 부족

대응:

- 초기에는 공개 표준단가 또는 상대비용을 사용한다.
- 비용산정식과 가정을 투명하게 표시한다.
- 실제 사업비 예측 정확도를 과도하게 주장하지 않는다.

## 리스크 5. 도면 인식 정확도 부족

대응:

- 초기 핵심 데모는 IFC 또는 구조화 입력으로 수행한다.
- 이미지 ML은 보완기능으로 배치한다.
- 사용자 수정 UI를 제공한다.

## 리스크 6. 자유형 평면생성의 복잡성

대응:

- 행동 후보를 미리 생성한다.
- 비내력벽, 문, 방화구획, 세대 통합 중심으로 제한한다.
- 구조체와 코어는 변경 불가 조건으로 둔다.

# 20. MVP 완료 기준

다음 조건을 모두 충족하면 MVP 완료로 본다.

1. 샘플 IFC 또는 건물 그래프 1개를 불러올 수 있다.
2. 현재 용도와 목표 용도의 규제 차이를 출력한다.
3. 최소 10개의 규칙을 자동검사한다.
4. 미충족 항목을 공간 또는 객체 ID에 연결한다.
5. 최소 5종의 개선행동 후보를 생성한다.
6. 규칙엔진이 불가능한 행동을 마스킹한다.
7. 탐욕, CP-SAT, 강화학습 결과를 비교한다.
8. 최소 3개의 개선대안을 출력한다.
9. 대안마다 세대 수, 비용, 기간, 적용행동을 표시한다.
10. 결과 보고서를 HTML로 생성한다.
11. 자동검토, 현장실측, 전문가 확인을 구분한다.
12. 모든 판정과 대안에 사용된 데이터 및 규칙 버전을 기록한다.

이 저장소에 LH CONVERT-GATE 연구용 MVP를 구축하라.

우선 전체 시스템을 한 번에 구현하지 말고 Phase 0과 Phase 1만 수행하라.

작업 완료 후 생성한 파일 목록, 주요 설계결정, 실행 명령어, 다음 Phase에서 필요한 작업을 요약하라.

# 23. 최종 기술 정의

LH CONVERT-GATE는 비주택 건축물의 도면과 BIM을 머신러닝으로 구조화하고, 현재 용도와 공공임대주택 용도 사이의 규제 차이를 규칙엔진으로 판정한 뒤, 법규를 하드 제약조건으로 적용한 강화학습과 수리최적화를 통해 최소개선 용도전환 대안을 생성하는 사전 의사결정 지원 시스템이다.
